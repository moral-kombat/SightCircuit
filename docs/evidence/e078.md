## Package I: session tokens for the mirror source

[E76](e076.md) found that no hardware source declared the HUD session tokens,
so a bound mask could never accept a mirror frame.
`framejacker/sources/session.py` now names one read-only source per token, and
`MirrorSource(..., session=MirrorSession(...))` declares the tokens to
`CaptureContext` and stamps each frame with them. No provider invents a value:
a token it cannot observe stays undeclared with a named reason, and a bound
mask rejects the frame with `hud_<token>_undeclared`. No command passes a
session yet: `scripts/mirror_recognize.py` calls `run_recognition` without
one, so only the library and its tests declare the tokens.

| Token | Source on a real run | Main unknowns (unverified on Frame) |
| --- | --- | --- |
| `timebase_id` | `HostClock`: the boot id, the `/proc/self/ns/time` namespace and its `CLOCK_MONOTONIC` offset, re-read for every frame | Whether the calibration writer shares the recognizer's time namespace; `CLOCK_MONOTONIC` stops during suspend |
| `session_id` | `RuntimeProcess`: the one `vrserver` process found by a bounded `/proc` scan, with the boot id, its pid and its start time | The runtime's process name on Frame; visibility across pid namespaces; a session change without a `vrserver` restart |
| `runtime_id` | `RuntimeProcess`: SHA-256 of the binary the process runs, read through `/proc/<pid>/exe`, never an install path or manifest | It covers `vrserver` only; `/proc/<pid>/exe` permission; an emulator or loader leaves it undeclared |
| `tracking_origin` | An injected `TrackingObserver`: the HMD universe id plus a digest of the zero-pose transforms | No native reporter exists, so on a real run this token stays undeclared and a bound mask rejects every frame |
| `recenter_epoch` | The same observer's count of recenter and chaperone events; it never resets | Whether Frame's recenter reaches an overlay client, and with what delay |

Done conditions, met in the cloud:

- a recenter event bumps `recenter_epoch`, and later frames bound to the old
  mask or context fail closed;
- a changed boot id changes `timebase_id`;
- a missing provider rejects frames with a named reason;
- a synthetic run with every token declared passes;
- `LIVE_IMAGE_INPUT` still refuses the mirror for HUD input, and
  `tests/test_gates.py` stays green.

The tests use a fake `/proc` root and hand-written events. 16 deliberately
broken copies of the code were each caught by them.

## Package J: neutral fill for the native HUD mask

This resolves the G5 mask-artifact question in [E76](e076.md), as the owner
chose: try a different fill and keep the strict rule. Each masked region
(footprint plus margin, per eye) is still zeroed at native resolution first,
and `unmasked_footprint_px` is still counted then. `hud.mask.fill_regions`
then fills each region with the rounded per-channel mean of the pixels within
8 px of it, in the same eye and outside every masked region, before the
resize. The strict overlap and eye rule is unchanged. A leak test shows that
changing any pixel inside a region leaves the detector input byte-identical.

Cloud results, on generated frames and public seed stills:

- **Gray sweep, 127 odd levels**, levels where the detector boxes the mask:

  | Detector | Zero fill | Every neutral fill |
  | --- | --- | --- |
  | MobileNetSSD | 93/127, as `tvmonitor` | 0/127 |
  | YOLOX-Nano | 0/127 | 0/127 |

  With the ring-mean fill, MobileNetSSD's highest sub-threshold box touching
  the mask scores 0.43, the same as without a mask.
- **Seed stills:** six stills with the mask pasted at five positions. Only the
  two inpainting fills produced an artifact-like box. With the ring-mean fill
  neither detector lost a clear detection (one that does not touch the mask).
  Next to the mask the strict rule still drops present hits with every fill:
  at the default `lower_right` position YOLOX keeps 9 of its 12 present hits
  for presentation with either fill, and the ring-mean fill keeps slightly
  fewer present hits than the zero fill at two positions (YOLOX 7 rather than
  9 at `fixture_scaled`, MobileNetSSD 2 rather than 3 at `center`). Seed pin
  counts without a mask still equal `evaluation/seed-expected.json`.
- **Cost per frame of the ring-mean fill:** about 0.7 ms at 1920×1080 at the
  default position and about 4 ms for the largest allowed region, against
  about 28 ms of MobileNetSSD inference. It is the cheapest of the neutral
  fills.
- **Strict-rule validation with the real default detector:**
  `scripts/live_pipeline.py --synthetic-check --synthetic-hud`, with and
  without `--validate-overlay`, now ends `completed`, exit 0, with every
  exclusion count 0. On `881fea7` it ended `validation_failed`, exit 1. A 60 s
  run covered 300 frames. The G1 rerun recipe is back on the default detector.

The full tables, the candidate fills and the limits are in
[neutral mask fill](../hud-qualification.md#neutral-mask-fill-2026-11-03).

## What stays open

- **Package I decision, taken after the merge:** the PR left open whether the
  tracking tokens should stay frozen when `MirrorSource` is created, or accept
  tokens that arrive later under explicit rules. On 2026-11-03 the owner kept
  binding at declaration
  ([owner decisions](../poc-scope.md#owner-decisions-2026-11-03)): a first
  tracking state must reach the observer before the source is created.
- Command path: no command passes a session to the mirror recognizer, and HUD
  input from the mirror stays refused by `LIVE_IMAGE_INPUT` until G4–G6 pass.
- Device follow-ups, each needing the owner's approval and none run:
  - run the token providers once, read-only, against the real `/proc` on Frame
    while SteamVR runs, checking the process name, pid-namespace visibility,
    `/proc/<pid>/exe` permission and target, and the time namespace;
  - a native tracking reporter in the bridge's real mode, with its own fixture
    and review, then a device check of recenter event delivery and its delay;
  - check the mask fill on real Frame mirror content once the qualified
    footprint is known. A flat surround-colored patch might still read as an
    object in some scene; if it does, the strict rule fails that run visibly.
- Offline follow-up: make the marker observer and
  `hud_validation_report.py --from-observer` record the providers' tokens
  instead of `--declared-context`.
