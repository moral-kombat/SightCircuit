# E91: Journal watchers left running after the A4 and A5 runs; a correction to E90 and an independent corroboration of its quiet run window

[Status and compatibility anchor](../status.md#e91-journal-watchers-left-running-after-the-a4-and-a5-runs-a-correction-to-e90-and-an-independent-corroboration-of-its-quiet-run-window)

## What was found

A read-only review of the staged F3 scripts found that the A4 and A5 run
scripts (`a4-run.sh`, `a5-run.sh`) had left their journal watchers running:
`kill $wpid` ended the wrapper shell, while the `g2-logwatch.sh` pipeline
(`journalctl -f | grep | tee -a <run>/watch.log`) kept running and appending
to the two evidence run directories. Six processes: 43392 to 43394 (started
18:28:08 EST on 2026-11-07, writing `run-dyhC7z/watch.log`, the A4 run of
[E89](e089.md)) and 63043 to 63045 (started 23:59:36 EST, writing
`run-9PH5yX/watch.log`, the A5 run of [E90](e090.md)). They only read the
journal; they modified no file but their own `watch.log`.

The Frame manager recorded both files, stopped exactly those six processes at
13:20 EST, and confirmed the files unchanged afterwards:

| File | Lines | SHA-256 |
| --- | --- | --- |
| `run-dyhC7z/watch.log` (A4) | 16 | `a24a696671068d4909565f19288e57c68e54e4f084a9109be4b194bb169f16db` |
| `run-9PH5yX/watch.log` (A5) | 1 | `495db0d9c3adf017b6da4e66e56a8cc885ee97318dc99e27aa1d049f7f42bbde` |

Every appended line lies outside its own run window. The A4 file holds the
18:40:46 standby entry and then the 23:58:34 to 23:59:28 wake sequence of the
A5 evening (wake, the IPE frame-processing failure with its re-submission, ICP
firmware 7.0.21, the external camera ownership request, colour cameras
disconnected, standby at 23:58:41 and wake at 23:58:52, ownership released at
23:59:27, colour cameras connected at 23:59:28), which [E90](e090.md) records
from the journal read afterwards. The A5 file holds one line, the 00:01:27
standby entry after that run. Neither file was edited; both now contain
post-run lines and are read with this record beside them.

## Correction to E90

E90 said the live watch log was empty "as on November 3 and 7" because the
live watch does not capture. That was wrong: the live watch does capture. The
files were empty during each run window because no matching event happened in
it. E90's sentence is corrected to point here; the counts and conclusions of
E89 and E90 are unchanged.

## Corroboration

The A4 watcher was still running through the whole A5 run window (23:59:37 to
23:59:57 EST) and logged nothing in it. A second, independent journal reader
therefore agrees with E90's post-run journal read that no camera-ownership,
colour-camera, IPE or standby event occurred during the A5 run.

## Consequences

The staged F3 run script starts its watcher in its own process group and stops
the group, and its leftover-process check names the watcher by its
`watch.log` path beside the bridge, worker and guardian. The same review also
replaced a preparation check that could never fire (a tree comparison after a
clean fast-forward pull) with an ancestry check against the reviewed F3a
revision and an abort when `tools/` or `scripts/build_*` differ from the
checkout, and made leftover processes a logged warning rather than a file
entry.

## Limits

A device report relayed by a peer session, recorded as received. Stopping
the six processes was the Frame manager's housekeeping of processes its own
scripts had left, reported here and not a device step of the work order; the
owner was told in the coordinator's session. The watcher files are records of
a journal filter, not of the camera subsystem's internal state; the G2
investigation's standing observation (an external camera ownership request one
to two seconds after a wake from standby, [E89](e089.md), [E90](e090.md)) is
unchanged.
