## What the run showed and what it did not

Shown: the hook, as installed and configured on the device, refuses the shell,
foreign-command, known-unsafe and forged-write classes in a live Claude Code
session, with its stderr line reaching the model; the runner refuses Tier B
and unknown ids; a Tier A task runs under the guard and the agent can write
its summary. The one case that only the hook could stop (line 6) was stopped
by the hook.

Not shown: the hook's verdict on an image Read, because the settings' Read
deny rule acted first at the Read tool's own path check; the Glob refusals,
because the tool was absent; the read-outside, read-private, network and
malformed-input classes in a live session (covered offline, 95 of 95, in both
modes). The guide's "hook runs first" expectation, taken from Claude Code's
documentation, did not hold as observed for a Read that a deny rule covers;
whether the hook ran and allowed it or was never reached is not visible,
since the hook writes nothing when it allows. The guide is revised: a Read
covered by a deny rule counts as `settings_denied`, not a guard failure; the
two Glob cases leave the recommended set; `permission_denials` is read as hook
blocks plus settings denials.
