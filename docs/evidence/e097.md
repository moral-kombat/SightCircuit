## Limits

A device report relayed by a peer session, recorded as received. It answers
the review's first device questions: the buffers are UBWC, not linear, so the
helper's `gpu_convert` path (Vulkan import by DRM modifier) is the one any
pixel step will take, and that path has never run on the Frame's driver; the
format is NV12 8-bit at 2464 by 2464 per camera; the service runs at 60 frame
sets a second; no format change and no control drift over about 10 s; the
exposure clock follows the monotonic domain with an offset of about a quarter
of a second whose meaning is not established. It does not answer standby
behaviour on headset removal. The white LED is the service's own activity
indicator, consistent with the agreement's requirement that camera activity be
obvious; the owner's consent rule ("the red LED untouched") was about
SightCircuit writing the LED, which it did not. No pixel was read. No
disturbance was reported, so the SDK track continues; any pixel step needs
its own approval.
