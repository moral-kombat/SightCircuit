`VkResult` −11 is `VK_ERROR_FORMAT_NOT_SUPPORTED`. The driver lists the
frame's modifier (`0x0500000000000001`) for NV12 with the right plane count
and as sampleable, since the helper's earlier checks passed, and refuses the
full image-format query the helper makes for it: a mutable-format image with
unsigned-integer per-plane views, sampled, imported from a DMA-BUF. No image
was imported and no pixel reached the parent. The command counted nine
non-JSON lines on the helper's error stream; their text is not kept.

## Limits

A device report relayed by a peer session, recorded as received. It shows
that the whole chain up to the pixel path works on the Frame with the real
service: the command's terminal confirmation, the supervised launch with the
parent's confirmation, the export stream's `ready` and `end`, the strict
reader, and a clean end with the reader off when the pixel path fails. It
shows that the helper's GPU import, as written, cannot import the service's
UBWC buffers on this driver; why the driver refuses that exact combination
(the mutable-format flag, the view formats, or UBWC import as such) is not
established. No frame reached the detector, so this is not the proof of
concept. No disturbance was reported, so the SDK track continues; the fix is
cloud work, and a rebuilt helper and a new run are a new device step under
the owner's approval.
