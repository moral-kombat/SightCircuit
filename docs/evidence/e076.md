## What changed

Each package was implemented test-first in its own worktree. Two or three
independent reviewers checked it, and a separate agent verified and fixed
their findings. The coordinator then merged the packages in dependency order.
After that, a branch-wide review ran: four reviewers, two adversarial
verifiers per finding, and one fixer.

- **A, still capture (blocker):** `mirror_recognize.py` had lost `--detector`
  and `--still` in `3bd3d4c`, so `frame_session.sh`'s stills stage exited 2.
  Both flags are restored. `--detector` builds through `create_detector`.
  `--still` saves the native, unannotated frame of the last processed result.
  The report and `frame_session_manifest.py --still-report` pin the still's
  SHA-256, detector, source and sequence, so a produced entry passes
  `evaluate_detectors.py --require-input-digests`. A contract test parses every
  `scripts/*.py` command line in `frame_session.sh` with that script's real
  parser. It fails on `9885f43` only on the stills line.
- **B, marker stop and guardian loss:** native marker mode never reads stdin.
  A requested marker stop therefore closes stdin and waits for the bridge's own
  deadline instead of sending SIGTERM at once. A V4-shaped frame-3 tag/bit
  rejection, run through the real validation bridge, worker and guardian, now
  cleans up with no forced termination; on `9885f43` the same case reproduced
  V4's forced stop.
  - Reports add `stop_requested` and `escalated`. Cancellation and overruns
    still escalate and are reported as forced.
  - The review hypothesis about guardian loss was **confirmed**: on
    `9885f43`, SIGKILL of the guardian left the worker group running. The
    supervisor now contains and reaps that group, and still reports
    `cleanup_ok: false`.
  - One `bridge_closed_cleanly()` replaces five copies.
  - None of this explains the green input, the tag mismatch or physical
    recovery.
- **C, checkpoint manifest:** `checkpoint_manifest.py --write/--verify` pins
  the following for the next G3 attempt. `--verify` is read-only and fails on
  any difference or a dirty tree.
  - git commit and a clean-tree check;
  - Python, platform and OS build;
  - the bridge built on that machine;
  - every library module, the checkpoint scripts, the native sources, the
    models and the checkpoint's third-party package versions.
- **D, one HUD contract:** `framejacker/hud/contract.py` owns every value
  Python and the bridge share, and generates the committed
  `tools/hud_contract.hpp`. CI checks it with `hud_contract_header.py --check`.
  - A validation-only bridge mode renders the native calibration marker.
    Tests require it to equal `observation.marker_template()` pixel for pixel,
    and require its tags to decode on a V4-shaped third read with zero tag and
    bit error.
  - **No mismatch was found.** The generator/template comparison therefore
    offers no candidate explanation for V4's tag/bit rejection, which stays
    unexplained.
- **E, qualification in the runtime:**
  - `hud_validation_report.py --from-observer` turns a clean observer report
    into a mapping candidate. At best that is `candidate_valid_unqualified`,

  - Runtime calibrations come only from a candidate record or the synthetic

  - One margin rule: 8–128 px, and at least the measured error terms plus

  - Pipeline `hud_checks` counts mask-overlap and eye-crossing rejections and
    unmasked footprint pixels. Synthetic HUD runs feed the validation ledger
    and report the template's `g5_software` counts. A detector that boxes the
    footprint fails the run.
- **F, one runner and one launcher:** `runtime/live.run_report` serves both the

## Findings that need a decision

- **Mask artifact (G5 design question):** on the generated 96×64 frames, the
  default MobileNetSSD reports the zeroed HUD mask itself as `tvmonitor`,
  confidence 0.51–0.81, on 93 of 127 uniform gray levels. Without the mask it
  reports nothing.
  - The runtime drops that box. Under the strict rule, though, a synthetic
    validation run with the real detector ends `validation_failed`, exit 1.
  - The G1 rerun recipe now uses `--detector fixture`, which ends
    `checked_unqualified`, exit 0.
  - Whether G5 should treat such a box differently, or fill the mask another
    way, is open. The rule was not loosened.
  - This is a cloud observation on generated frames, not Frame behaviour.
- **Real-source session tokens:** no hardware source declares session tokens
  yet. A bound HUD mask rejects a frame without them, so a future adapter must
  declare them.
