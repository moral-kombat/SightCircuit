## Established software sequence

1. Two baseline frames were read before marker submission. The third read
   succeeded, then its marker analysis returned zero complete copies and one
   orphan fragment, with failed tag-pattern/code-bit checks. No valid mapping
   samples were accepted. The error was `orphan_marker_tag_or_incomplete_copy`.
   The capture wrapper's generic `acquisition_failed` label came from this
   callback rejection; it does not demonstrate a read/I/O failure.
2. That exception bypassed the observer's normal wait for the marker timer.
   Its `finally` called the marker client's `close()` while the native process
   was still alive. The pinned marker client has no frame-writer thread; the
   pinned overlay client therefore marked forced termination and immediately
   requested SIGTERM. It did not first wait for the five-second display timer.
3. Native cutoff was 213.437 ms after native startup, 27.741 ms after the
   rejected frame's observation, and 4,786.563 ms before its display deadline.
   Native code handled the stop, reported `status: stopped`, returned from
   cleanup 2.414 ms after cutoff and exited 0 with `cleanup_ok: true`.
4. Overall cleanup remained false because the client had requested termination.
   The outer worker and guardian reported no forced termination; the overall
   supervision time was 0.636 seconds. This was not their deadline path.

Thus the early software stop and the apparently different cleanup fields are
explained by the exact tested source and recovered report. The conservative
overall cleanup result must remain false. No native crash is established.
The report records one generated marker frame, no inference and no expiring
input frames; the later SSD normalization and guarded opcode-4 offset fixes
are not explanations of this run's software sequence.
